# Authentication and Authorization



## 1. Identification



SolanaTokenManager є локальним консольним застосунком

для створення та управління SPL-токенами у блокчейні Solana.



У поточній реалізації використовується однокористувацький

режим роботи.



Ідентифікація за унікальним іменем користувача

передбачається у подальшому розвитку системи.



## 2. Authentication



Основним методом автентифікації є пароль.



Для хешування та перевірки паролів використовується bcrypt.



Параметри автентифікації:



- Алгоритм хешування: bcrypt.

- Коефіцієнт складності: 12.

- Випадкова сіль під час хешування.

- Приховане введення пароля.

- Перевірка відповідності пароля його хешу.

- Обмеження кількості спроб входу.



Багатофакторна автентифікація TOTP передбачається

як можливість подальшого розвитку системи.



## 3. Credential Storage



Для перевірки пароля використовується його криптографічний хеш.



Вимоги до зберігання облікових даних:



- Заборона зберігання відкритих паролів.

- Заборона публікації конфіденційних даних у Git.

- Заборона виведення паролів у консоль.

- Обмеження доступу до конфіденційних даних.

- Використання захищеного локального сховища.



Зберігання облікових записів у файлі users.json

є запланованим розширенням.



## 4. Registration



У поточній версії окремий механізм реєстрації

користувачів не реалізовано.



Модуль auth.rs містить функцію hash_password

для формування криптографічного хешу пароля.



Реалізовано перевірку таких параметрів:



- Пароль не може бути порожнім.

- Максимальна довжина пароля становить 72 байти.

- Хешування виконується алгоритмом bcrypt.



Для майбутнього механізму реєстрації передбачається:



- Перевірка унікальності імені користувача.

- Мінімальна довжина пароля 12 символів.

- Хешування пароля.

- Захищене зберігання облікового запису.



## 5. Login



Автентифікація виконується перед початком

основних операцій програми.



Послідовність автентифікації:



1. Запуск програмного забезпечення.

2. Запит пароля користувача.

3. Приховане введення пароля.

4. Перевірка пароля за допомогою bcrypt.

5. Надання доступу у разі успішної перевірки.

6. Зменшення кількості доступних спроб у разі помилки.

7. Відмова в доступі після трьох невдалих спроб.



Максимальна кількість спроб автентифікації

за один запуск програми становить 3.



Після вичерпання спроб програма завершує роботу

без виконання захищених операцій.



Повторний запуск програми відновлює лічильник спроб.



## 6. Session Management



Поточна реалізація використовує локальний сеанс

у межах одного запуску програми.



Після успішної автентифікації користувач отримує

доступ до основної логіки застосунку.



Після завершення роботи програми доступ припиняється.



Для повторного запуску необхідно знову пройти

автентифікацію.



Окремі токени сеансу та механізми автоматичного

завершення сеансу за тайм-аутом не реалізовано.



## 7. Authorization



Доступ до основної логіки SolanaTokenManager

надається лише після успішної автентифікації.



У поточній реалізації захищено доступ до таких операцій:



- Генерування криптографічних пар ключів.

- Підготовка інструкції створення Mint Account.

- Підготовка інструкції ініціалізації SPL-токена.

- Підготовка Associated Token Account.

- Підготовка інструкції випуску токенів.

- Формування та підписання транзакції.



Для роботи використовується тестова мережа Solana Devnet.



Поточна версія формує та підписує транзакцію,

але не надсилає її до блокчейну.



Розмежування доступу за ролями та окремими дозволами

передбачається у подальшому розвитку системи.



## 8. Security Testing



Для перевірки механізмів автентифікації реалізовано

модульні тести у файлі src/auth.rs.



| Тест | Призначення | Результат |

| --- | --- | --- |

| correct_password | Перевірка правильного пароля | Passed |

| incorrect_password | Перевірка неправильного пароля | Passed |

| empty_password | Перевірка порожнього пароля | Passed |

| long_password | Перевірка надмірної довжини пароля | Passed |



Для запуску модульних тестів використовується команда:



&#x20;   cargo test



Результати тестування:



- Виконано тестів: 4.

- Успішно пройдено: 4.

- Неуспішно пройдено: 0.



Також виконано ручне функціональне тестування:



- Успішна автентифікація з правильним паролем.

- Відхилення неправильного пароля.

- Відмова в доступі після трьох невдалих спроб.

- Підготовка транзакції після успішної автентифікації.

## 11. Conclusion



У межах лабораторної роботи №4 реалізовано базові

механізми автентифікації та обмеження доступу

до програмного забезпечення SolanaTokenManager.



Використання bcrypt, прихованого введення пароля

та обмеження кількості спроб входу підвищує

рівень захищеності застосунку.



Результати модульного та ручного тестування

підтверджують працездатність реалізованих механізмів

у перевірених сценаріях.
