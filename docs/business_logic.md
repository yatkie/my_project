
# SolanaTokenManager BUSINESS LOGIC

> Документ описує бізнес-логіку програмного модуля для створення, ініціалізації та управління SPL-токенами в блокчейні Solana. Відображає поточну реалізацію програми на Rust.

## Purpose

`SolanaTokenManager` відповідає за:
- Створення нового SPL-токена в мережі Solana.
- Ініціалізацію токена із заданою кількістю десяткових знаків.
- Отримання адреси асоційованого токен-акаунта власника.
- Випуск початкової кількості токенів.
- Переказ токенів між акаунтами.
- Взаємодію з мережею Solana через RPC.

**NOT here:**
- Реалізація повноцінного лістингу токена на Pump.fun — не реалізована.
- Управління користувачами та авторизація — не реалізовані.
- Графічний інтерфейс користувача — не реалізований.
- Зберігання історії операцій у базі даних — не реалізоване.

## Entities

| Entity | Basic Fields | Description | Invariants |
|---|---|---|---|
| `TokenMint` | pubkey, decimals, mintAuthority | Представляє створений SPL-токен у мережі Solana. | - Адреса токена повинна бути валідним Pubkey.<br>- Кількість decimals визначається під час ініціалізації.<br>- Mint Authority визначає право випуску токенів. |
| `TokenAccount` | address, owner, mint | Представляє токен-акаунт, який зберігає токени певного власника. | - Повинен бути пов'язаний із конкретним токеном.<br>- Повинен мати визначеного власника.<br>- Баланс не може бути від'ємним. |
| `Wallet` | pubkey, keypair | Представляє гаманець, який підписує та оплачує транзакції. | - Публічний ключ визначає адресу гаманця.<br>- Приватний ключ використовується для підпису транзакцій.<br>- Приватний ключ не повинен передаватися стороннім особам. |
| `TokenTransfer` | source, destination, amount | Описує операцію переказу токенів між акаунтами. | - Кількість переказу повинна бути більшою за нуль.<br>- Відправник повинен мати достатній баланс.<br>- Транзакція повинна бути підписана уповноваженим власником. |

> Зазначені сутності описують предметну область. У поточній реалізації вони представлені структурами та типами бібліотек Solana, а не окремими власними класами або структурами проєкту.

## Token Lifecycle

Життєвий цикл токена складається з таких етапів:

| Stage | Description |
|---|---|
| `CREATED` | Створення облікового запису Mint у мережі Solana. |
| `INITIALIZED` | Ініціалізація токена та встановлення кількості decimals. |
| `MINTED` | Випуск початкової кількості токенів. |
| `TRANSFERRED` | Виконання переказу токенів. |
| `LISTING_PENDING` | Очікування інтеграції з Pump.fun. |

- Початковий стан токена — створення Mint Account.
- Наступний етап — ініціалізація через SPL Token.
- Випуск токенів виконується через інструкцію `mint_to`.
- Переказ виконується через інструкцію `transfer`.

> Стани наведені як концептуальні етапи бізнес-процесу. У програмі окрема статусна машина поки не реалізована.

## Token Creation Flow

Основний процес створення токена:

1. Створюється RPC-клієнт для підключення до Solana Mainnet.
2. Генерується гаманець `payer`.
3. Генерується новий ключ `mint` для токена.
4. Визначається кількість десяткових знаків — 9.
5. Отримується мінімальний баланс для звільнення від орендної плати.
6. Створюється Mint Account.
7. Виконується ініціалізація токена.
8. Виводиться адреса створеного токена.

**Boundary:** Модуль відповідає за створення токена та його початкову ініціалізацію. Реалізація лістингу на сторонніх платформах не входить до поточної реалізації.

## Token Distribution Flow

Процес випуску та переказу токенів:

1. Отримується адреса Associated Token Account власника.
2. Формується інструкція `mint_to`.
3. Виконується випуск початкової кількості токенів.
4. Отримується адреса одержувача.
5. Формується інструкція `transfer`.
6. Відправляється транзакція переказу.
7. Виводиться повідомлення про результат операції.

## Value Objects

| Value Object | Description | Invariants |
|---|---|---|
| `Pubkey` | Публічний ключ акаунта або токена в мережі Solana. | - Має валідний формат публічного ключа.<br>- Використовується для ідентифікації акаунтів. |
| `Keypair` | Пара ключів для підпису транзакцій. | - Містить приватний та публічний ключі.<br>- Приватний ключ повинен зберігатися конфіденційно. |
| `TokenDecimals` | Кількість десяткових знаків токена. | - У поточній реалізації встановлено значення 9. |
| `TokenAmount` | Кількість токенів, що передається або випускається. | - Представляється цілим числом `u64` у мінімальних одиницях токена.<br>- Значення операції повинно бути більшим за нуль. |
| `SolanaRpcUrl` | Адреса RPC-сервера для взаємодії з мережею Solana. | - Повинен містити коректну адресу RPC-сервера.<br>- У поточній реалізації використовується Solana Mainnet Beta. |

## Domain Policies

| Domain Policy | Description |
|---|---|
| Token Creation Policy | Створення Mint Account повинно виконуватися з коректними параметрами та необхідним балансом для оренди. |
| Token Initialization Policy | Ініціалізація токена повинна містити адресу Mint Account, адресу власника та кількість decimals. |
| Minting Policy | Випуск токенів дозволяється лише уповноваженому Mint Authority. |
| Token Transfer Policy | Переказ повинен мати визначений токен-акаунт відправника, одержувача та коректну кількість токенів. |
| Wallet Security Policy | Приватні ключі повинні зберігатися в безпечному середовищі та не публікуватися. |
| Transaction Confirmation Policy | Результат операції повинен перевірятися після відправлення транзакції в мережу. |

## Domain Services

У поточній реалізації окремий шар Domain Services відсутній. Бізнес-операції виконуються безпосередньо у функції `main()`.

| Operation | Description |
|---|---|
| Create Token | Створення нового Mint Account. |
| Initialize Token | Ініціалізація SPL-токена. |
| Mint Tokens | Випуск початкової кількості токенів. |
| Transfer Tokens | Переказ токенів іншому одержувачу. |

## Domain Events

Окрема система Domain Events у поточній версії не реалізована.

Інформація про виконання операцій виводиться через `println!`:

- Повідомлення про створення токена.
- Повідомлення про нарахування токенів.
- Повідомлення про початок лістингу.
- Повідомлення про переказ токенів.

## Application Commands & Queries

У поточній реалізації окремі Application Commands та Queries не створені.

Операції викликаються послідовно з функції `main()`.

**Commands:**

| Command | Purpose |
|---|---|
| `CreateToken` | Створення нового SPL-токена. |

**Queries:**

| Query | Purpose |
|---|---|

> Назви Commands та Queries є логічним описом операцій, а не окремими реалізованими структурами програми.

## Infrastructure

Для взаємодії з блокчейном використовується екосистема Solana та бібліотеки Rust.

### Libraries

- `solana_client` — підключення до RPC-сервера Solana.
- `solana_sdk` — робота з ключами, транзакціями та публічними адресами.
- `spl_token` — створення, ініціалізація та управління SPL-токенами.
- `spl_associated_token_account` — отримання адрес Associated Token Account.
- `std::str::FromStr` — перетворення рядка на публічний ключ.

### RPC Configuration

- RPC URL: `https://api.mainnet-beta.solana.com`
- Network: Solana Mainnet Beta.
- Transaction confirmation: через RPC-клієнт.

### Security

- Не публікувати приватні ключі.
- Не зберігати секретні ключі безпосередньо у відкритому коді.
- Перевіряти адресу одержувача перед переказом.
- Перевіряти баланс перед виконанням транзакцій.
- Використовувати лише перевірені RPC-сервери.

### Current Limitations

- Відсутня обробка помилок через повноцінний механізм `Result`.
- Відсутня окрема система логування.
- Відсутня перевірка результатів усіх транзакцій.
- Відсутнє автоматичне створення Associated Token Account.
- Інтеграція з Pump.fun поки не реалізована.
- Відсутній окремий модуль управління конфігурацією.
